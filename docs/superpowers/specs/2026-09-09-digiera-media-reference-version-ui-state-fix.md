# DIGIERA Media RC1 — Reference Version UI State Fix

Date: 2026-09-09
Branch: `feature/digiera-media-v1-rc1-versioning`

## User-observed symptom

Replace/version history/FOLLOW_CURRENT/PINNED_VERSION all work functionally through v3, but reopening the DIGIERA Media modal visually defaults to `Luôn dùng phiên bản mới nhất` even when the existing reference is persisted as `PINNED_VERSION`.

## Root cause

The persisted database state was correct. The UI reopen data path was incomplete:

- `ui.open()` always initialized `versionmode = 'FOLLOW_CURRENT'` and `pinnedversionid = 0`.
- `resolve_references` did not return `reference.versionmode` or `reference.pinnedversionid`.
- TinyMCE reference components did not retain authoritative reference version state after hydration.
- There was no API to update an existing reference in place, so the modal only supported creating a new reference.

Version mode is intentionally per-reference, not per-media. Multiple references to one Media may legitimately use different modes/versions.

## Fix

Product version: `2026090901` / `1.0.0-rc1-fasttrack-versioning2`.

Implemented:

- `resolve_references` returns `versionmode`, `pinnedversionid`, and media metadata required to reopen the selected reference.
- New AJAX endpoint `local_digieramedia_update_reference_version` updates the existing reference UUID in place.
- TinyMCE component hydration stores media UUID, version mode and pinned version id in non-persisted component data attributes while marker persistence remains unchanged.
- `ReferenceComponent.getSelectedReference()` identifies the existing component selected in TinyMCE.
- Opening DIGIERA with an existing component selected loads authoritative DB state and preselects the same media + saved Follow/Pin mode.
- Save action becomes `Cập nhật reference` while editing an existing reference; no duplicate reference/marker is created.
- Selecting another media switches back to new-reference semantics and the button returns to `Chèn vào bài`.
- Generic modal open with no existing component selected intentionally defaults to FOLLOW_CURRENT because it represents a new reference.

## Browser acceptance

User browser verification on 2026-09-09 confirms the original UI-state defect is resolved:

- Existing DIGIERA component is selected in TinyMCE before opening the modal.
- The same Media is reopened automatically.
- `Ghim một phiên bản` is restored as selected for an existing pinned reference.
- The saved pinned version (observed as `v1`) is restored in the version dropdown.
- Version history still shows `v3` current with `v2` and `v1` retained.
- Save action is `Cập nhật reference`, confirming edit-existing-reference semantics rather than creating a new reference.

Observed browser state therefore verifies the authoritative persisted reference version state now round-trips back into the modal UI.

Remaining acceptance checks for this feature family are optional regression confirmations: switch existing reference PINNED -> FOLLOW_CURRENT -> reopen, then FOLLOW_CURRENT -> PINNED v1 -> reopen, while keeping the marker UUID unchanged.
